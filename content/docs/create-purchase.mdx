Use `createPurchase()` to initiate an online checkout transaction.

```typescript
const result = await aba.createPurchase({
  transactionId: "TXN_1740001",
  amount: 15.50,
  currency: "USD",
  items: "Order #9921",
  firstName: "Rith",
  lastName: "Sila",
  email: "rith@example.com",
  phone: "012345678",
  returnUrl: "https://myshop.com/orders/success",
  cancelUrl: "https://myshop.com/orders/cancel",
});
```

## Currency and Amount Rules

The SDK automatically formats amount values according to ABA rules:

- **USD (`USD`)**: Formatted to two decimal places (`15.5` → `15.50`).
- **KHR (`KHR`)**: Formatted to whole integers (`40000.25` → `40000`).

## Return Values (`PurchaseResponse`)

```typescript
interface PurchaseResponse {
  readonly success: boolean;
  readonly transactionId: string;
  readonly checkoutUrl?: string;     // Web checkout redirect URL
  readonly abapayDeeplink?: string;  // Opens ABA Mobile on this payment
  readonly appStoreUrl?: string;     // Fallback: no ABA Mobile installed (iOS)
  readonly playStoreUrl?: string;    // Fallback: no ABA Mobile installed (Android)
  readonly qrString?: string;        // Raw EMV QR string for KHQR
  readonly qrImage?: string;         // Ready-to-render QR, as a PNG data URI
  readonly amount: number;
  readonly currency: string;
  readonly error?: string;
  readonly errorCode?: string;       // ABA's status code when success is false, e.g. "1" (wrong hash), "21" (expired key)
}
```

<Callout title="checkoutUrl is not always present" type="warn">
ABA's current API mainly answers with a KHQR code (`qrString` and
`qrImage`), not a web checkout link. Don't assume `checkoutUrl` will be
set — check for it before using it, and prefer showing the QR code
instead. See [KHQR Generation](/docs/khqr) for how to display it.
</Callout>

`qrImage` is a PNG that ABA renders for you — you can put it straight in an
`<img src>` with no extra work. Use [`generateKHQR`](/docs/khqr) only if you
want a styled card instead of ABA's plain QR image.

## Paying on a phone

If your customer is already on a phone — a Telegram mini app, a mobile web
checkout, a WebView — don't show them a QR code they'd need a second device to
scan. Pass `paymentOption: "abapay_khqr_deeplink"` and ABA also returns
`abapayDeeplink`, which opens ABA Mobile directly on the payment:

```typescript
const purchase = await aba.createPurchase({
  transactionId: generateTransactionId(),
  amount: 4.5,
  currency: "USD",
  items: "Order #9921",
  paymentOption: "abapay_khqr_deeplink",
  returnDeeplink: {
    ios_scheme: "myapp://order/42",
    android_scheme: "myapp://order/42",
  },
});

window.location.href = purchase.abapayDeeplink!;
```

See [ABA App Deeplink](/docs/deeplink) for the full flow, including the
fallbacks for a phone without ABA Mobile and why you must still verify the
payment server-side.

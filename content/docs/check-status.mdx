---
title: Checking Status
description: Polling and querying transaction payment state
---

Query the status of any transaction using `checkStatus()`:

```typescript
const response = await aba.checkStatus("TXN_1740001");

if (response.success) {
  console.log("Status:", response.status);
  console.log("Paid Amount:", response.amount);
  console.log("Payment Time:", response.paymentTime);
} else {
  console.error(`Query failed (code ${response.errorCode}):`, response.error);
}
```

---

<Callout title="Critical: Only APPROVED Means Paid" type="warn">
<strong>A refused card NEVER produces a "DECLINED" status.</strong>

When a card is refused, ABA displays error 57 with a "Try Again" button on the hosted checkout page and leaves the transaction <strong>open for retry</strong>. As a result, <code>checkStatus()</code> continues to return <code>PENDING</code>. Verified against ABA's live sandbox: a transaction refused with a declined test card remained <code>PENDING</code> minutes later.

- **Never write** <code>if (status === "DECLINED") cancelOrder()</code> — it will not fire for a card refusal.
- **Never cancel or expire an order** because an attempt failed in the user's browser; the customer may retry and succeed.
- Only settle orders when status is <code>APPROVED</code>.
</Callout>

---

## Possible Payment Statuses

| Status | Meaning | What to do |
| :--- | :--- | :--- |
| `APPROVED` | Payment completed and settled. | Settle order and deliver goods. |
| `PENDING` | Awaiting payment or open for retry. | Keep waiting / polling. Card refusals stay here. |
| `DECLINED` | Terminal decline from bank. | Do not rely on this for card refusal. |
| `REFUNDED` | Transaction refunded. | Update order state. |
| `ERROR` | API query failed. | Check `errorCode` and retry. |

---

## Error Codes Are Per-Endpoint

<Callout title="Do not use a single shared error table" type="info">
ABA error codes are specific to each endpoint, not global across the API. For example:
- **Code 6 on `checkStatus` (`check-transaction-2`)**: Means "Transaction not found".
- **Code 6 on `createPurchase` (`purchase`)**: Means "Domain not whitelisted".
</Callout>

### `check-transaction-2` Status Codes

| Code | Meaning | Note |
| :--- | :--- | :--- |
| `0` | Success | Transaction found and reported. |
| `1` | Wrong Hash | Merchant ID and API key do not match. |
| `6` | Transaction not found | **Normal for ~1 second after creation** before it becomes queryable. Retry after a short delay. |
| `21` | End of API lifetime | API key expired. Must request renewal from ABA. |

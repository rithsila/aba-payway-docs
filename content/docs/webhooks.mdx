When a customer pays, ABA PayWay posts a JSON callback (pushback) to your webhook URL with signature header `X-PayWay-HMAC-SHA512`.

Use `verifyWebhook()` to validate the notification:

```typescript
verifyWebhook(
  payload: string | Record<string, unknown>,
  signature: string,
  secret?: string
): Promise<boolean>
```

---

## How `verifyWebhook()` Works

The method implements ABA's exact pushback verification algorithm:

1. **Sorts JSON keys ascending**: Orders the body keys alphabetically (`ksort`).
2. **Concatenates values only**: Joins values together with no keys and no separators.
3. **Calculates HMAC-SHA512**: Hashes the concatenated string using the secret key.
4. **Encodes to Base64**: Matches ABA's signature format.
5. **Constant-time comparison**: Compares bytes with an XOR accumulator (`^`) to protect against timing attacks.

### Three Important Properties

1. **Raw body is not required**: ABA builds the signature from parsed values, not raw request bytes. A framework-parsed body (`await req.json()`) works identically to a string, and incoming key order does not matter.
2. **Secret is optional**: The method falls back automatically: `secret` → `config.webhookSecret` → `config.apiKey`. You do not need to pass it explicitly if you already configured your client.
3. **Never throws**: Bad signatures, malformed bodies, or missing headers return `false` instead of throwing an error.

## Code Example

```typescript
import { ABAPayWay } from "aba-payway-sdk-unofficial";

const aba = new ABAPayWay({
  merchantId: process.env.ABA_MERCHANT_ID!,
  apiKey: process.env.ABA_API_KEY!,
  baseUrl: process.env.ABA_BASE_URL || "https://checkout.payway.com.kh",
});

export async function POST(req: Request) {
  const body = await req.json();
  const signature = req.headers.get("x-payway-hmac-sha512") ?? "";

  // 1. Verify signature without needing raw text
  const isValid = await aba.verifyWebhook(body, signature);
  if (!isValid) {
    return new Response("Invalid signature", { status: 401 });
  }

  // 2. Always confirm with checkStatus() — do not trust payload.status alone
  const payment = await aba.checkStatus(body.tran_id);
  if (payment.status === "APPROVED") {
    // 3. Settle the order. Handler MUST be idempotent!
    // ABA may deliver the same pushback more than once.
  }

  return new Response("OK", { status: 200 });
}
```

---

<Callout title="Which key signs the pushback?" type="warn">
ABA's sample code says only <code>YOUR_SECRET_KEY</code>. The SDK defaults to using your <code>apiKey</code> because that is the only shared secret ABA issues to merchants. This detail has not been confirmed by ABA in writing.
</Callout>

<Callout title="Testing limitation & Domain Whitelisting" type="info">
The pushback signature scheme is implemented and unit-tested against an independent implementation. However, it has not been verified against a live ABA callback in production, which requires a publicly reachable <code>return_url</code> whitelisted by ABA. Note that ABA rejects non-whitelisted callback domains with error <strong>code 81</strong>.
</Callout>

---

## Best Practices

- **Make handlers idempotent**: Pushback notifications can arrive more than once for the same transaction. Ensure your system does not duplicate order fulfillments or credits.
- **Always verify with `checkStatus()`**: Treat webhook pushbacks as a fast notification signal, but verify final state against the check-transaction API before releasing goods or services.

on it to reject fake payment notifications until this is fixed. Read

When a customer pays, ABA PayWay can send a notification to a `callback_url`
you provide. ABA signs it with an `X-PayWay-HMAC-SHA512` header so you can
check the message really came from ABA and wasn't changed along the way.

## How ABA signs a callback

Based on ABA's own sample code, the signature is built like this:

1. Take all the fields in the callback body.
2. Sort them by field name, A to Z.
3. Join the values together into one string (no separators).
4. HMAC-SHA512 that string, then Base64-encode it.
5. Compare it to the `X-PayWay-HMAC-SHA512` header.

**What key signs it is not confirmed.** ABA's sample just calls it
`YOUR_SECRET_KEY` without saying which credential that is. It is most likely
your **Public Key** (the same one used as `apiKey`), since that's the only
shared secret ABA gives you — but treat this as a guess until ABA confirms it
in writing.

## What `verifyWebhook()` actually does today

```typescript
async verifyWebhook(payload: string, signature: string, secret: string): Promise<boolean>
```

It HMAC-SHA512s the **raw request body as one string** — not the sorted,
concatenated fields described above. So it will not produce the same
signature ABA sends, and will reject every real ABA callback.

The comparison itself is done safely (constant-time, so a timing attack can't
guess the right answer one byte at a time) — the problem is only in what
gets hashed, not how it's compared.

**Until this is fixed:** don't gate anything important on `verifyWebhook()`.
If you need to react to a payment right now, use [`checkStatus()`](/docs/check-status)
to ask ABA directly instead of trusting an unverified webhook body.

## There is no "webhook secret" from ABA

You may see `ABA_WEBHOOK_SECRET` in older examples. ABA does not issue a
webhook secret — it isn't on the credential sheet, and there's no dashboard
page that generates one. Don't spend time looking for it.

## Example (once verification is fixed)

```typescript
import { ABAPayWay } from "aba-payway-sdk-unofficial";

export async function POST(req: Request) {
  const rawBody = await req.text();
  const signature = req.headers.get("x-payway-hmac-sha512") || "";

  // Using your Public Key here is a best guess — see "How ABA signs a
  // callback" above. Confirm with ABA before relying on this in production.
  const isValid = await aba.verifyWebhook(rawBody, signature, process.env.ABA_API_KEY!);

  if (!isValid) {
    return new Response("Invalid signature", { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("Verified Transaction:", payload.tran_id, payload.status);

  return new Response("OK", { status: 200 });
}
```

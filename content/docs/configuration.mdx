Initialize `ABAPayWay` by passing an `ABAConfig` object:

```typescript
import { ABAPayWay, type ABAConfig } from "aba-payway-sdk-unofficial";

const config: ABAConfig = {
  merchantId: "ec460802",
  apiKey: "your_public_key_here",
  baseUrl: "https://checkout-sandbox.payway.com.kh",
};

const aba = new ABAPayWay(config);
```

---

## Configuration Properties

| Option | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `merchantId` | `string` | Yes | "Merchant Id" on your ABA credential sheet. |
| `apiKey` | `string` | Yes | "Public Key" on your ABA credential sheet. This is a secret — it's the HMAC-SHA512 key used to sign every request, despite the name. |
| `baseUrl` | `string` | Yes | "API Url" on your ABA credential sheet. You can paste the full URL ABA gave you, or just the origin — the SDK keeps only the origin either way. |
| `webhookSecret`| `string` | No | Accepted, but not read by anything yet. See [Webhooks](/docs/webhooks) — it's an unfinished feature, not a working option. |

---

## Your ABA credential sheet, mapped

ABA gives you five items when you register. Here's what each one is for:

| On the sheet | Goes in | Used for |
| :--- | :--- | :--- |
| Merchant Id | `merchantId` | Every request. |
| Public Key | `apiKey` | Signing every request (HMAC-SHA512). |
| API Url | `baseUrl` | Which server to call (sandbox or production). |
| RSA Public Key | *(not used)* | Payout/refund APIs, which ABA turns on per merchant on request. Not used by anything in this SDK. |
| RSA Private Key | *(not used)* | Same as above. |

If you don't see an "RSA Public/Private Key" pair on your sheet, that's
fine too — you don't need them.
